Approach

How I build things that survive being handed over.

Cost the current state first

Almost every failed improvement case skipped the baseline. Anecdote is not a number, and a savings figure nobody can trace back to a step, a role, and an hour will not survive its first serious question.

Write down the limits

Every model here publishes what it assumes and where it breaks. Stating the boundary is what separates analysis from advocacy, and it is the part reviewers check first.

Build for the handoff

Anything only its author can run is a liability, not infrastructure. Clear inputs, an exportable trail, a written summary someone else can defend in a meeting they attend without me.

Let it say no

A tool that only ever returns a favourable answer is a sales deck. These are built so that the unfavourable result — don't automate this, don't write this line — comes out just as clearly.

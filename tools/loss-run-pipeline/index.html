Tool 01 · Claims data

Loss-Run Pipeline

A third-party administrator sends a loss run every morning. This is the agent that turns it into something a reserving actuary and a board can rely on: it standardises the file, finds what is wrong with it, reconciles it to yesterday's, and holds the release when a human needs to look first.

Synthetic dataDeterministicRuns in your browserSelf-tested
  Any loss run with a claim number, insured, line, loss date, status, paid and reserve column will map. Nothing leaves your browser.

Exceptions

What was wrong with the file

Blocking exceptions quarantine the row: it does not reach the actuarial export, and the release is held until someone resolves or accepts it. Warnings are corrected or carried, and listed so the correction is visible.

Activity

What changed since the prior run

The activity report is the difference between two standardised snapshots. It is what the claims manager reads each morning: new claims, closures, reopenings, and any reserve that moved by more than the threshold.

Standardisation

How the file was read

Column mapping is by pattern, so a renamed header still lands. Every format conversion is counted; the count is the evidence that the file was not clean and the pipeline did not silently guess.

Exports

What leaves the pipeline

Three files. The actuarial export is the canonical claim listing with personal data removed; the activity report; and the exception file that goes back to the administrator.

Method

Assumptions on the surface

Data
A synthetic captive book: five operating companies, three lines, eight policy years, generated from a seed committed to the repository. The raw file is produced from that book with deliberately mixed formats and a fixed set of injected defects, so every finding can be checked against the truth.
Duplicates
When a claim number appears twice, the later row wins. Administrators append corrections; they rarely prepend them.
Incurred
Incurred is always recomputed as paid plus outstanding. The administrator's incurred column is read only to detect disagreement.
Personal data
Any column recognised as a claimant name is used for nothing and excluded from every export.
Release gate
Blocking exceptions, new claims at or above the large-claim threshold, and claims that vanished from the file all hold the release. Nothing downstream refreshes until a named person releases it.
Tests
node tools/loss-run-pipeline/selftest.mjs checks that every injected defect is found and that untouched claims round-trip to the cent.
Synthetic data throughout. Nothing here derives from any real insurer, insured, or claimant. nealpathak.github.io
